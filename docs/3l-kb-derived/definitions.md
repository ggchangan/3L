## 1. 总体层级

3L 原文不是“看见一个技术信号就交易”，而是先确定背景，再在关键位置识别供需行为，最后才形成买卖点。

工程层级应固定为：

```text
静态关键点
  ↓
波段
  ↓
结构 / 阶段
  ↓
供需事件：衰竭点、转折点、中继点、失败点、高潮/恐慌
  ↓
交易信号：买点 / 卖点 / 观察 / 回避
```

这里有一个非常重要的边界：

- 静态关键点是锚点，不直接说明买卖；
- 波段是走势分段，不直接说明大结构；
- 结构决定概率环境，不直接等于供需事件；
- 供需事件是量价解释，不直接等于交易动作；
- 买卖点必须在市场环境、方向/主线、结构阶段、供需事件共同成立后才输出。

## 2. 静态关键点：参考点

### 原文依据

- `trading_system/关键点1_参考点.md`
  - 关键点包括容易观察到的前高、前低；
  - 包括不寻常的量价行为，如成交量明显放大或萎缩、长阳、长阴、十字星；
  - 前高、前低、天量 K 线、地量 K 线的高低点，容易形成支撑/阻力和心理锚定。

### 工程定义

静态关键点只回答：

```text
这根 K 或这个价位是否值得被标记为锚？
```

它不回答：

```text
这里是否买入？
这里是否卖出？
这里是否需求占优？
```

### 当前代码映射

- `server/backend/core/pure_keypoint_detector.py`

当前方向基本正确：

- `price_high`：局部前高 / 压力锚；
- `price_low`：局部前低 / 支撑锚；
- `volume_peak`：局部量峰 / 天量候选；
- `volume_trough`：局部量谷 / 地量候选。

注意：代码里的“天量/地量”现在采用局部窗口 + 均量/分位数，不是历史绝对最大/最小。这符合工程可落地，但后续文案应叫“局部量峰/局部量谷”，不要夸大成绝对天量地量。

## 3. 波段

### 原文依据

- `training_camp/13_波段交易程序及要点.md`
  - 波段是把走势拆成一段一段观察和操作；
  - 波段分为上升段和下降段；
  - 操作任务是把握上升段、回避下降段；
  - 峰谷是波段的终点和起点，能识别峰谷就能识别波段；
  - 趋势中包含若干小波段。

### 工程定义

波段只回答：

```text
当前这一段价格运行方向是什么？
上一段和下一段的起止在哪里？
```

波段不是结构本身。比如：

```text
上升趋势中的下降波段 = 回调
下降趋势中的上升波段 = 反弹
区间震荡中的上升波段 = 摆动到区间上沿
```

### 当前代码映射

- `server/backend/core/wave_structure_detector.py`
- `server/backend/core/supply_demand_transition_zone_detector.py`

当前 P0.3 的“多日供需转换区间”只是波段切换骨架，不能直接当作 3L 完整供需转换。

## 4. 结构与阶段

### 原文依据

- `trading_system/走势结构与阶段.md`
- `training_camp/14_强弱结构判断及买卖点匹配.md`

原文明确结构分三类：

- 上升趋势：需求占优；
- 下降趋势：供应占优；
- 区间震荡：供需相对均衡。

阶段决定操作意义：

- 上升趋势形成/发展：可持股，或选择突破/中继买点；
- 上升趋势加速/逆转：提高警惕，等待卖点，不能重仓新入；
- 下降趋势形成/发展：应回避；
- 下降趋势恐慌/逆转：可能产生左侧/右侧买点；
- 区间震荡：关注两头，区间中部不宜强行解释。

### 工程定义

结构不直接定义供需事件，但决定同一个量价行为的含义。

例子：

```text
缩量回踩：
  在上升趋势中，可能是供应不足，中继候选；
  在下降趋势中，可能只是无需求阴跌，不是低吸理由。

放量滞涨：
  在上升末端，可能是需求衰竭/供应进入；
  在低位初期，不能机械当成顶部。
```

因此，供需事件识别必须带结构上下文。

## 5. 供需格局转换关键点

### 原文依据

- `trading_system/关键点2_转换点.md`
  - 原有供需格局被打破的位置就是关键点；
  - 供需格局被打破的位置会出现突破点、反转点、中继点；
  - 突破点是趋势形成点；
  - 中继点是趋势延续点；
  - 反转点是趋势逆转位置。
- `liangjia_yuanli/量价原理_全文.md`
  - 供需格局转换点不是绝对点，更应该理解为区域；
  - 先衰竭，再转折；
  - 衰竭点是左侧，转折点是右侧。

### 工程定义

供需事件应分成五类，而不是全部混成“买点”：

| 事件 | 含义 | 常见方向 | 是否交易决策 |
|---|---|---|---|
| `exhaustion` 衰竭点 | 原方向力量衰减 | bullish 或 bearish | 否 |
| `reversal` 转折点 | 新力量出现并尝试压倒旧力量 | bullish 或 bearish | 否 |
| `continuation` 中继点 | 反向力量无法改变原格局 | bullish 或 bearish | 否 |
| `failure` 失败点 | 突破/跌破尝试失败 | bullish 或 bearish | 否 |
| `climax/panic` 高潮/恐慌 | 一致性买入或卖出导致力量透支 | bullish 或 bearish | 否 |

所有供需事件都应带：

```json
{
  "event_type": "exhaustion|reversal|continuation|failure|panic|climax",
  "direction": "bullish|bearish|neutral",
  "side": "demand|supply|balance",
  "status": "candidate|confirmed|failed",
  "position_context": {},
  "wave_context": {},
  "structure_context": {},
  "volume_price_evidence": {},
  "is_trade_decision": false
}
```

## 6. 中继点的边界

### 原文依据

- `trading_system/关键点2_转换点.md`
  - 中继点是无法改变原有趋势的量价行为出现的位置；
  - 常见于上升趋势缩量回踩、下降趋势无量反弹；
  - 中继点一般伴随缩量，力量小才无法改变原趋势。
- `trading_system/四种买点.md`
  - 中继买点是上升趋势中缩量回踩；
  - 特征是“正在涨 + 跌不动”，顺大势逆小势；
  - 适用背景包括突破回踩、上升趋势回踩、区间底部。

### 工程规则

中继不能只因为出现“上涨趋势”或“短期回落”就成立。

看多中继至少需要：

```text
大背景：上升趋势，或区间底部，或突破后回踩；
小波段：当前处在回调/下行小波段；
位置：接近支撑、均线、突破位、区间下沿等关键锚；
量价：缩量、波动收窄、未破关键点；
含义：供应不足，无法改变需求占优格局。
```

看空中继至少需要：

```text
大背景：下降趋势；
小波段：反弹；
量价：无量反弹、需求不足；
含义：需求无法改变供应占优格局。
```

因此：

```text
区间顶部不能标为看多中继买点。
放量上涨不能标为缩量回踩中继。
下降趋势缩量阴跌不能标为低吸中继。
```

## 7. 四类买点

### 原文依据

- `trading_system/四种买点.md`
- `training_camp/13_波段交易程序及要点.md`
- `training_camp/16_波段交易真实案例解析.md`

### 工程定义

| 买点 | 供需含义 | 必要条件 | 常见市场 |
|---|---|---|---|
| 突破买点 | 需求放量打破平台/压力 | 放量、突破关键位、最好强势市场 | 强势/主线 |
| 中继买点 | 供应不足，无法改变需求占优 | 上升趋势或区间底部，缩量回踩关键点不破 | 强势/平衡 |
| 反转买点 | 需求出现并反转原调整/下降 | 供应先衰竭，随后放量反转/突破 | 弱转强/下降末期 |
| 恐慌买点 | 快速供应出清后的左侧机会 | 下跌末端，天量滞跌/恐慌，需后续需求确认 | 弱势/恐慌 |

买点输出应是 `trade_signal` 层的结果，不应由供需事件层直接输出。

## 8. 当前代码差异清单

### P0.1 `pure_keypoint_detector.py`

需要后续优化：

- 输出文案从“天量/地量”谨慎改为“局部量峰/局部量谷”；

### P0.2 `supply_demand_keypoint_detector.py`

状态：可借鉴，但需要重构语义。

主要差异：

- 当前 `transition_points` 同时包含突破、跌破、反转、中继、恐慌、高潮，但没有统一的 `event_type`；
- `bullish_continuation` 容易被前端理解成“中继买点”，但原文中中继必须证明“无法改变原供需格局”，不是普通技术信号；
- 恐慌买点原文核心是下跌末端的恐慌/天量滞跌，当前代码已有 `panic_stagnation`，但仍需更严格绑定“下跌末端/低位/支撑附近”；
- 供需事件和交易信号边界还不够硬，容易导致前端显示“观察/买点/结构”互相矛盾。

### P0.3 `supply_demand_transition_zone_detector.py`

状态：保留为实验旁路。

主要差异：

- 当前只是使用波段方向切换作为多日区间骨架；
- 还没有把静态关键点、结构边界、衰竭点、转折点分层纳入；
- 后续应变成供需事件状态机的一个输入，而不是直接当供需转换结论。

- 不允许再用字符串包含判断买点；
- 不允许把区间顶部显示成看多中继买点；

- 每个算法字段必须能解释：来自静态关键点、波段、结构、还是量价行为。
