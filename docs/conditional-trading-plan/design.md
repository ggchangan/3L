# 条件交易计划设计

## 目标

把复盘页的“买入、持有、卖出”等名词结论升级为次日能够检查的条件计划，同时保持职责边界：复盘页生成建议，工作台筛选、保存和跟踪计划。

训练营对计划的要求是：持仓必须说明什么情况下继续持有、什么情况下卖出；候选股必须说明次日出现什么形态才买入；系统性或意外风险必须预先定义退出方式。盘中只执行计划，不临时发明交易理由。

## 数据契约

每个持仓操作和买点信号增加以下兼容字段：

- `trigger_condition`：如果发生什么。
- `action_when_triggered`：条件成立后做什么。
- `invalidation_condition`：什么情况使计划失效。
- `stop_condition`：止损条件。
- `valid_for`：有效期，当前为下一交易日。
- `plan_readiness`：`ready` 或 `needs_stop`。

旧字段继续保留，避免历史复盘缓存和工作台日志失效。

## 生成规则

买点条件严格按突破、中继/回踩、反转、恐慌四类生成。系统当前没有可靠输出具体压力位和支撑位，因此第一版只描述结构确认条件，不虚构价格。已有止损价时生成明确价格止损；没有止损价时明确提示导入工作台后补充，未补充前不执行买入。

`decision_status` 与 `plan_readiness` 共同构成执行门禁：

- `executable`：条件触发后按计划买入。
- `candidate`：触发后重新评估，不能自动升级成买入。
- `signal_only`：只观察。
- `blocked`：等待数据闭环。

即使方向和买点满足 `executable`，只要缺少有效正数止损价，也必须降级为 `candidate + needs_stop`，进入工作台观察区；0、负数、布尔值、NaN 和无穷大都会被清空，不能进入价格报警。

条件文案不能绕过市场环境、主线/强动量方向、个股买点和止损四层约束。

## 页面与工作台

复盘页在原有原因链之前展示“如果、那么、失效、止损、有效期”。工作台导入时使用 `trigger_condition` 作为计划条件，并完整保存失效、止损和有效期字段；观察项仍进入观察列表，可执行项才进入买入列表。

## 后续边界

具体突破价、支撑价和自动条件报警需要由买点算法输出结构化关键位后再接入，不能从自然语言猜测。工作台计划编排和跟踪体验属于后续控制台优化，不在本次改造中扩展。
