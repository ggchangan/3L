# 3L 多日供需转换区间识别器 P0.3 设计

> 状态：实验旁路。只用于人工校验和后续算法迭代，不接入生产复盘页、不输出买卖点。

## 背景

3L 体系中的交易不是单根 K 线判断，而是围绕波段和关键位置观察供需格局变化。P0.1 已经识别“前高、前低、天量、地量”等纯关键点；P0.2 在单日上下文中识别“突破、跌破、反转、中继、恐慌滞跌、高潮滞涨”等供需格局点。但真实行情里，供需转换经常不是一天完成：

- 下降段转上升段：先止跌、再承接、再向上确认；
- 上升段转下降段：先滞涨、再失守、再向下确认；
- 最新一天可能刚开始切换，只能标记为形成中，不能提前当成确认。

因此 P0.3 新增“多日供需转换区间”识别层，专门回答：某个波段从下行切到上行，或从上行切到下行时，转换发生在哪几天、证据是什么、是否确认。

## 三层关系

```text
P0.1 纯关键点
  只描述锚点：前高、前低、局部量峰、局部量谷等。

P0.2 单日供需格局点
  描述某一天是否出现供应/需求打破、承接、衰竭、延续等信号。

P0.3 多日供需转换区间
  描述一段波段切换窗口：下降→上升、上升→下降。
```

P0.3 可以引用 P0.2 作为证据，但不会替代 P0.2；P0.3 也不会输出“买入/卖出”，因为买卖点还需要结合主线、市场环境、个股位置和交易计划。

## 输入

- `klines`: 日 K，至少包含 `date/open/high/low/close/volume`。
- `asset_type`: `market | sector | stock`，沿用 P0.1/P0.2 的资产类型。
- 可选 `wave_states`: 由 `judge_wave_structure()` 滚动生成的波段状态，用于测试或复用外部计算。
- 可选 `supply_demand_results`: 由 `detect_supply_demand_keypoints()` 滚动生成的单日供需点，用于测试或复用外部计算。

## 伪算法

```text
1. 标准化 K 线并按日期排序。
2. 对每一天滚动调用 judge_wave_structure()，取 trading_wave.direction。
3. 把连续相同 trading_wave.direction 合并为波段片段。
4. 只关注相邻片段中的 down→up、up→down。
5. 对每个切换点建立多日区间：
   - start = 切换日前 pre_bars 个交易日；
   - end   = 切换日后 post_bars 个交易日，最新数据不足则截断；
   - pivot = 新波段第一天。
6. 在区间内聚合证据：
   - 前一波段方向、持续天数、跌/涨幅；
   - 新波段方向、持续天数、早期涨/跌幅；
   - 区间量能相对前 10 日均量；
   - 区间价格推进幅度；
   - 区间内是否有方向一致的 P0.2 供需点。
7. 生成状态：
   - confirmed：新波段持续至少 2 天且综合证据达到阈值；
   - forming：最新区间证据不足但方向正在切换；
   - failed：切换后 1 天内又反向，说明尝试失败。
```

## 设计边界

- 这是“转换区间”识别，不是买卖点识别。
- 区间允许多天，避免把供需转换误压缩成一根 K 线。
- 最新一天的区间优先标记为 `forming`，除非已有足够连续证据。
- JSON 保留全量切换候选；图表和页面应优先展示 `tier=core` 或与人工锚点/最新交易日相关的区间，避免把每一次小波段摆动都解释成同等级供需转换。
- 第一版先使用波段方向切换作为骨架，P0.2 单日供需点作为加权证据；后续可以继续加入结构级别的前高/前低突破、箱体上下沿和筹码承接验证。
