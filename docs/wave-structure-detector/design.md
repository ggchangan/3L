# 3L 波段结构识别 P0 实验设计

> 状态：实验旁路，不接入生产。
> 目标：验证“先识别波段，再判断结构/供需转换”的路线是否比旧 EMA 三分类更符合 3L 波段操作。

## 1. 背景

旧结构算法 `get_structure()` 是 EMA 确认型趋势算法：

```text
EMA12斜率 + BIAS + EMA5/10/20排列 + EMA5斜率 + 最近3日收盘斜率
```

它的优点是稳定、纯函数、易回归；但在 3L 波段操作场景里存在两个问题：

1. 趋势确认滞后。
   例如科创50 2026-06-08 到 2026-06-30 有一大波上涨，但旧算法到
   2026-06-25 才识别为上涨趋势。
2. 趋势容易被短期扰动打断。
   例如科创50 2026-07-10 后进入明显下降波段，但 2026-07-21 的反弹会让旧
   算法短暂回到区间震荡。

这会直接影响后续供需转换点：

```text
上涨波段中的缩量回踩 → 可能是上涨中继；
下降波段中的缩量反弹 → 可能是下跌中继；
如果结构先错，供需点也会错。
```

## 2. 思路转变

3L 讲的是波段操作，因此结构层不应只从均线确认出发，而应先回答：

```text
当前主导波段是什么？
这个波段从哪里开始？
现在是否仍在这个波段内？
短期反向波动是否足以改变主导波段？
```

再由波段状态派生结构：

```text
主导上涨波段 → 上涨趋势 / 上涨形成中 / 上涨回踩
主导下降波段 → 下降趋势 / 下降形成中 / 下降反弹
没有足够主导波段 → 区间震荡
```

## 3. 第一版算法：动态 ZigZag 波段

第一版采用“动态反转阈值”的 ZigZag 思路：

```text
反转阈值 = max(固定最小反转幅度, ATR百分比 × 倍数)
```

不同对象的默认阈值：

| 对象 | 最小反转幅度 | ATR倍数 | 用途 |
|---|---:|---:|---|
| market | 3% | 1.8 | 大盘波段，噪音较低 |
| sector | 4% | 2.0 | 板块波段，轮动更快 |
| stock | 5% | 2.2 | 个股波段，噪音更大 |

算法流程：

```text
输入 K 线
  ↓
计算 ATR14 百分比
  ↓
用动态阈值识别 confirmed pivots
  ↓
最后一个 confirmed pivot 到当前极值/当前价构成 active_wave
  ↓
如果 active_wave 涨跌幅超过阈值 → 结构为上涨/下降趋势
  ↓
如果当前只是反向回撤但未超过反转阈值 → 保持原主导波段
  ↓
否则 → 区间震荡
```

## 4. 输出契约

第二版输出必须把“大级别结构”和“当前交易波段”拆开：

```text
structure / phase
  用于描述大级别结构：市场背景、风险偏好、是否仍在主升/主跌结构中。

trading_wave / trading_state
  用于描述当前正在交易的波段：当下是上涨波段、下降波段、反弹波还是回调波。
```

这是 3L 波段交易里非常重要的区别。交易不应只看一个“上涨趋势/下降趋势”
标签，而要知道当下所处的可交易波段。例如：

```text
中证全指 2026-05-14 ~ 2026-06-11：
  大级别结构：前半段仍可视为上涨趋势
  当前交易波段：下降波段
  组合状态：上涨趋势中的下降波段/回调

交易含义：
  这段不能按上涨推动波处理；即使主结构未完全反转，也应按回调/风险段处理。
```

```json
{
  "version": "wave-structure-v1",
  "date": "20260721",
  "asset_type": "market",
  "structure": "下降趋势",
  "phase": "countertrend_bounce",
  "trading_wave": {
    "direction": "up",
    "label": "上涨波段",
    "start_date": "20260720",
    "start_price": 1530.0,
    "extreme_date": "20260721",
    "extreme_price": 1603.0,
    "change_pct": 4.8,
    "counter_move_pct": 0.0,
    "confirmed": true
  },
  "trading_state": "下降趋势中的反弹波",
  "active_wave": {
    "direction": "down",
    "start_date": "20260710",
    "start_price": 1790.0,
    "extreme_date": "20260720",
    "extreme_price": 1530.0,
    "change_pct": -14.5,
    "counter_move_pct": 4.8,
    "confirmed": true
  },
  "thresholds": {
    "reversal_pct": 4.2,
    "atr_pct": 2.3
  },
  "pivots": [
    {"date": "20260612", "type": "low", "price": 1500.0},
    {"date": "20260710", "type": "high", "price": 1790.0}
  ],
  "reason": "主导下降波段未被反向反弹阈值破坏，仍视为下降趋势中的反弹"
}
```

> 兼容说明：`active_wave` 是算法内部视角；`trading_wave` 是交易/展示视角。
> 当前版本两者字段多数相同，但调用方应优先读取 `trading_wave` 和
> `trading_state`，避免把主结构标签误当成当前交易方向。

### 4.1 candidate 当前交易波段

主结构继续使用 confirmed pivots，保持稳定；当前交易波段允许使用 candidate
反向波，提升交易层对当下波段的敏感度。

触发逻辑：

```text
如果 active_wave 是上涨波：
  从活动波高点以来，最大回撤 >= candidate_reversal_pct；
  且当前收盘仍保留至少 60% 的 candidate 触发强度；
  则 trading_wave = 下降波段，source = candidate_counter_wave。

如果 active_wave 是下降波：
  从活动波低点以来，最大反弹 >= candidate_reversal_pct；
  且当前收盘仍保留至少 60% 的 candidate 触发强度；
  则 trading_wave = 上涨波段，source = candidate_counter_wave。
```

其中：

```text
candidate_reversal_pct = max(min_impulse_pct, reversal_pct × 0.60)
```

设计原因：

1. 3L 是波段交易，当前交易波段不能完全等待主结构确认；
2. 暴涨后的快速回落，应尽早表达为“上涨趋势中的下降波段/回调”；
3. 但单日长下影/长上影后收回，不应仅因日内极值就翻转交易波段。

普冉股份样本：

```text
2026-06-30：
  盘中/区间回撤存在，但收盘收回较多；
  trading_wave 仍保持上涨波段。

2026-07-02：
  从 2026-07-01 高点后出现足够回撤；
  trading_wave 切为下降波段；
  trading_state = 上涨趋势中的下降波段/回调。
```

## 5. 与旧结构算法的关系

本算法不替换生产的 `get_structure()`。

短期计划：

```text
旧 EMA 结构：继续生产使用
波段结构：旁路输出、生成验证图、人工校准
```

验证通过后，再考虑在 P0.2 供需转换点中优先使用波段结构。

## 6. 第一批验收样本

先用科创50验证两个关键场景：

1. 2026-06-08 ~ 2026-06-30
   - 人眼：一大波上涨；
   - 旧算法：直到 2026-06-25 才确认上涨趋势；
   - 目标：波段结构应更早识别上涨波段。

2. 2026-07-10 ~ 2026-08-03
   - 人眼：一大波下降；
   - 旧算法：2026-07-21 的反弹会打断下降结构；
   - 目标：波段结构应保持下降趋势/下降反弹，而不是直接回到区间震荡。

验收时不看买卖点，只看结构是否更接近肉眼波段。

## 7. 第一版实验结果

使用科创50真实 K 线初跑，第一版动态 ZigZag 有两个结论：

### 7.1 有效改善：上涨波段识别更早

科创50 2026-06-08 到 2026-06-30：

```text
旧 EMA 算法：
  2026-06-25 才确认上涨趋势。

波段实验算法：
  2026-06-10 起识别为上涨趋势；
  active_wave 从 2026-06-08 低点开始；
  到 2026-06-30，波段涨幅约 40%。
```

这更接近人眼对“一大波上涨”的识别。

### 7.2 暴露问题：主跌中的强反弹仍可能过早翻多

科创50 2026-07-10 到 2026-08-03：

```text
2026-07-13 ~ 2026-07-20：
  波段实验算法识别为下降趋势。

2026-07-21 ~ 2026-07-28：
  因 2026-07-20 后反弹幅度较大，第一版会暂时翻成上涨趋势。

2026-07-29 ~ 2026-08-03：
  再次识别为下降趋势。
```

这与人工判断存在差异。人工更倾向认为：

```text
2026-07-21 是主跌中的扰动/反弹；
如果没有该扰动，下降波段大概率延续到 2026-08-03；
因此 2026-07-21 不应轻易把主结构翻为上涨趋势。
```

这说明波段算法还需要引入“主导波段/次级反弹”的层级判断：

```text
新反向波段不应只因超过 ZigZag 阈值就改变主结构；
还要判断它是否改变了前一主导波段的高低点结构、持续性和回撤比例。
```

## 8. 下一步论证：主导波段与次级波段

第二版不应只输出一个 active_wave，而应输出：

```text
dominant_wave     主导波段
secondary_wave    次级反弹/回踩
structure         由主导波段决定
phase             impulse / pullback / countertrend_bounce / transition
```

主跌中的反弹只有满足以下条件之一，才允许改变主结构：

```text
1. 反弹收复前一主跌波段的关键压力；
2. 反弹幅度达到前一主跌幅度的较高比例，并且持续站稳；
3. 后续回踩不再创新低，形成更高低点；
4. 出现明确需求进入和供需反转证据。
```

否则应保持：

```text
structure = 下降趋势
phase = countertrend_bounce
```

上涨趋势中的回踩完全对称：

```text
未跌破主升波段关键支撑前，不应因短期回调直接降级为区间震荡。
```

## 9. 2026-08-27 口径修正：交易按当前波段执行

人工复核新增两个样本后，确认第一版最大问题不是完全识别不到反向波段，
而是把“大级别结构”和“当前交易波段”混在一个背景色里展示：

```text
科创50 2026-05-26 ~ 2026-06-09：
  当前下降波段已经成立；
  但算法仍显示为“上涨趋势 / 回调波”。

中证全指 2026-05-14 ~ 2026-06-11：
  5/15 起 active_wave 已经是 down；
  6/08 才把大结构切成下降趋势；
  5/15~6/05 的背景仍偏上涨，容易误读。
```

修正后的验收标准：

1. 图上必须同时展示主结构和当前交易波段；
2. “上涨趋势中的下降波段/回调”不能被展示成简单的“上涨趋势”；
3. 买卖点后续不得只依赖 `structure`，而应结合 `trading_state` 和关键点；
4. 交易动作以当前波段和关键点为核心，主结构只提供背景和风险偏好。
