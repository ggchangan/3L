# 3L 买点识别与持仓止损生命周期设计

## 1. 问题与目标

绿的谐波（688017）在 2026-07-31 经历急跌后出现放量长阳，符合“下降/调整末端需求重新进入”的反转买点语义。现有系统因为 20 日量比硬门槛返回 `hold`，随后持仓止损误走非 3L 的 `cost - 2ATR` 路径，最后又被同日结构支撑覆盖。最终数值接近正确值，但信号、止损来源和解释都不正确。

本次改造目标：

1. 完整实现突破、中继、反转、恐慌四类买点。
2. 分离“量价信号存在”“环境是否适配”“最终操作计划”三个层次。
3. 持仓保存建仓买点及止损锚点，使止损可追溯。
4. 初始风险止损与持仓后的动态保护止损分开，禁止同日伪装成结构抬高。
5. 量比周期、阈值、数据质量和降级原因可解释。

## 2. 知识库约束

- 突破/反转买点用于改变原有供需格局，必须出现需求，表现为明显放量且价格收在相对高位。
- 中继买点不改变原格局，要求上涨趋势或区间底部的缩量回踩。
- 恐慌买点发生在下降末端或区间底部，供应集中释放后还需观察需求能否持续。
- 市场环境影响买点选择、优先级、节奏和仓位，不抹掉已经发生的个股量价信号。
- 止损必须对应“证明买入逻辑错误”的位置：突破/反转/恐慌信号 K 线或关键点下方，中继回踩低点下方。

## 3. 三层输出契约

| 层次 | 字段 | 含义 |
|---|---|---|
| 信号事实 | `technical_signal`, `buy_point`, `technical_confidence` | 个股量价是否形成四类买点，不受市场门禁覆盖 |
| 环境适配 | `decision_status`, `attention_reason` | 市场、主线、阶段是否支持执行 |
| 操作计划 | `action_type`, `trigger_condition`, `invalidation_condition` | 买入、观察、持有、减仓、卖出等实际动作 |

`technical_signal=buy` 不等于立即买入。弱势环境中的反转信号可以存在，同时被标记为“观察/候选”。

## 4. 反转与恐慌识别

### 4.1 反转买点

硬前提：

- 最近 20 日从高点回撤至少 7%；
- 信号日为阳线，收盘位于当日振幅中位以上；
- 未继续有效创新低，或创新低后明显收回；
- 需求量价确认满足以下任一组合：
  - 20 日量比 ≥ 1.30；
  - 5 日量比 ≥ 1.30，且实体占振幅 ≥ 0.50；
  - 涨幅 ≥ 7%，实体占振幅 ≥ 0.55，且成交量高于前一日。

通过硬前提后再按下降幅度、收盘位置、20/5 日量比、实体、供应萎缩/恐慌背景、站回 EMA5 评分。阈值和各分项必须随结果返回，不能只返回“放量不足”。

### 4.2 恐慌买点

恐慌释放是左侧供应事件，不自动等同右侧反转。必须记录：

- `panic_release`：大跌、大振幅、放量或极端成交量；
- `demand_confirmation`：随后停止创新低、收回关键位或出现需求 K 线。

只有供应释放和需求确认同时存在才输出可执行的恐慌买点；仅有供应释放时输出观察信号。

## 5. 止损生命周期

持仓保存以下字段：

- `entry_signal_type`：突破买点/中继买点/反转买点/恐慌买点/手工；
- `entry_signal_date`：买点日期；
- `entry_anchor_price`：证明买点失败的锚点；
- `stop_loss_source`：信号K线/关键结构/ATR降级/手工；
- `original_stop_loss_price`：建仓初始止损；
- `stop_loss_price`：当前执行止损。

计算顺序：

1. 优先使用已保存的买点类型和锚点。
2. 未保存时按买入日期自动识别历史买点，并让用户确认。
3. 明确买点：按信号 K 线或关键结构失效位计算。
4. 无法识别买点且复权数据完整：才允许 ATR 降级。
5. `adjustment_status` 不完整时禁止把 ATR 作为正式建议，只显示“数据质量不足，需人工设定”。

动态保护止损只有同时满足以下条件才可上移：

- 最新交易日晚于买点日；
- 买入后形成新的有效更高支撑；
- 新保护位高于当前止损且低于当前价格；
- 页面展示新旧锚点和上移原因，用户确认后保存。

## 6. 回归与上线门槛

- 固定绿的谐波 2026-07-31 为反转买点回归样本，止损锚定信号日低点。
- 增加反例：只有大涨但无下降背景、缩量反抽、收盘低位、继续创新低，不得误报反转。
- 比较修改前后的反转信号数量、5/10/20 日最大有利/不利波动、假信号率和覆盖率。
- 四类买点分别统计，不用总体指标掩盖某一类型恶化。
- 全量测试、自动代码审查和生产只读验证通过后上线。
