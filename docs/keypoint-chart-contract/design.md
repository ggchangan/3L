# 3L 关键点图统一契约

## 目标

大盘、行业、概念和个股图必须使用同一套关键点语义，并严格区分：

1. 第一类关键点：前高、前低、天量、地量，是锚定参考位；
2. 第二类关键点：突破、反转、中继，是供需格局转换或延续点；
3. 量价证据：放量上涨、放量下跌、缩量、放量滞涨，只描述行为；
4. 技术信号：技买、技卖，是个股量价事实，不代表通过复盘门禁；
5. 交易决策：买、卖，只能来自带完整上下文的最终卡片决策。

第一类关键点和量价证据都不能单独冒充买卖点。前低只是潜在支撑，只有价格在该位置出现供应衰竭、吸收或需求进入，才可能形成买点；前高同理。

## 知识库依据

《3L交易体系构建》将关键点分成两类：

- 明显参考点：前高、前低、天量 K 线高低点、地量 K 线高低点；
- 供需格局改变的位置：突破点、反转点、中继点。

知识库同时强调，关键位置必须配合量价行为分析。最低点无法自证，因此图表不得把局部最低点直接解释为需求已经占优。

## 输出字段

每个图表关键点保留 `idx/label/y`，并增加：

```json
{
  "kind": "reference | volume_evidence | transition | technical_signal | decision | evidence",
  "direction": "bullish | bearish | neutral",
  "explanation": "自解释说明",
  "is_trade_decision": false,
  "is_executable": false
}
```

SVG 使用 `<title>` 暴露解释文本，鼠标停留在关键点时可以查看。后续算法扩展不得绕过该契约。

## 数据约束

- 个股、行业、概念和指数 K 线必须先经过数据访问层；图表服务不能单独直连第三方数据源；
- 图表只消费权威 K 线和决策快照，不重新推导页面最终交易动作；
- 数据日期或内容变化必须使缓存失效。
