# 3L 买卖点统一判定契约

本文档用于约束后端买卖点计算、复盘页导出、个股分析页展示和关键点图标记，避免同一只股票同时出现“区间顶部 / 中继买点 / 减仓 / 买入”等互相冲突的结论。

## 知识库依据

依据 3L 知识库中《量价原理》第 5.6、5.7 节与训练营《不同市场背景下的策略选择》《如何判断恐慌》《不同波段买点的止损点设置》：

1. 交易只在关键点和关键信号发生时才具备概率优势；关键点是静态位置，关键信号是动态量价行为。
2. 上涨中继发生在上涨趋势中，量价行为是缩量回踩且不破坏原有上升趋势。
3. 区间震荡只重点交易两头：
   - 区间顶部无法突破，是卖点或减仓点；
   - 区间顶部放量有效突破，才是突破买点；
   - 区间底部无法跌破并获得支撑，是买点；
   - 区间底部有效跌破，是卖点。
4. 恐慌买点是天量滞跌，只能出现在下降趋势末端或区间底部附近；上涨趋势高位放量长阴不是恐慌，而是供需转坏。
5. 弱势市场主要匹配恐慌、反转、底部确认类买点；强势市场主要匹配突破和趋势回踩买点。
6. 大盘采用排除法：只要不处于主跌段，就继续盯方向和个股买卖点；主跌风险是新增仓位的硬门禁。

## 统一计算顺序

```text
个股结构/阶段（关键点）
    ↓
按关键点过滤允许出现的买卖点类型
    ↓
运行关键信号检测（量价行为）
    ↓
生成 technical_signal：技术事实
    ↓
生成 execution_signal：结合关键点后的执行倾向
    ↓
复盘层叠加市场环境、方向/主线、止损完整性，决定 executable/candidate/signal_only/blocked
```

## 买点类型与允许位置

| 类型 | 允许位置 | 必要信号 | 不允许场景 |
|---|---|---|---|
| 突破买点 | 上涨趋势中的有效突破；区间顶部有效放量突破 | 向上突破 | 区间中段、下降趋势普通反弹 |
| 上涨中继买点 | 上涨趋势中 | 缩量回踩、不破坏上升趋势 | 区间顶部、下降趋势 |
| 区底支撑买点 | 区间震荡的区间底部 | 滞跌、缩量/放量承接、无法向下突破 | 区间顶部、区间中段 |
| 反转买点 | 下降趋势末端或区间底部附近 | 向上反转、需求重新占优 | 上涨趋势高位、区间顶部 |
| 恐慌买点 | 下降趋势末端或区间底部附近 | 天量滞跌 | 上涨趋势高位、区间顶部 |

## 卖点类型与优先级

| 类型 | 位置/信号 | 操作语义 |
|---|---|---|
| 向下突破 | 区间底部有效跌破 | 卖出 |
| 向下反转 | 上涨趋势末端出现供应涌现 | 卖出 |
| 需求衰竭 | 加速、放量滞涨、缩量滞涨 | 减仓/卖出预警 |
| 结构转弱 | 下降趋势、转弱、下行 | 卖出/换股 |
| 区间顶部受阻 | 区间顶部无有效突破 | 减仓 |

## 字段契约

- `technical_signal`：量价技术事实，值为 `buy/sell/hold`。出现技术信号不等于可执行。
- `signal` / `execution_signal`：结合关键点后的执行倾向，值为 `buy/sell/hold`。
- `buy_point`：经过关键点门禁后的买点名称。与关键点冲突时不得保留为正式买点。
- `decision_status`：复盘层最终执行状态：
  - `executable`：可进入交易计划；
  - `candidate`：候选观察；
  - `signal_only`：只有技术信号；
  - `blocked`：数据或市场门禁阻断。
- 前端只能展示这些最终字段，不应重新推导“买入/观察/减仓”。

## 当前系统的量化近似

知识库原文是自然语言体系，代码必须用可计算条件近似：

- 结构/阶段：用 EMA、近 N 日高低位、成交量状态近似；
- “天量”：当前实现用 20 日量比和前 20 日最大量近似；
- “滞跌”：用收盘位置、下影线、小实体近似；
- “区间顶部/底部”：用近区间价格位置近似。

这些近似必须在信息提示里展示依据值，并通过后续人工标注/回归样本继续校准。
